# ❄️ SNOW Clan Monitor — 2.1.0

بوت رسمي في سيرفر سنو للأوامر واللوق، وقارئ `discord.py-self==2.1.0` بحسابك الموجود في أرينا لقراءة العضوية والرتب المتاحة. يحفظ الحالة وطابور اللوق واعتماد القارئ المشفّر في MongoDB.

أزيل أمر التفاعل ونظامه وأزراره ورصد الرسائل والصوت، وحُذفت مكتبة القارئ القديمة من المتطلبات. تبقى البيانات القديمة الموجودة في قاعدة البيانات دون حذف تلقائي؛ لا يستمر تسجيل نشاط جديد.

## التحديث والتشغيل

تحتاج الاستضافة **Node.js 22.12+ أو 24 وPython 3.10+ مع venv/pip**. إذا كانت صورة Wispbyte توفر Node فقط، تحتاج صورة تشغيل تدعم الاثنين؛ رفع ملفات Python لا يثبت المفسر.

1. أوقف التشغيل القديم، وارفع محتويات مجلد المشروع كاملًا. احتفظ بملف `.env` وإعدادات الاستضافة و`ENCRYPTION_KEY` وMongoDB الحاليين. لا يكفي استبدال `src/index.js` وحده.
2. نفذ:

   ```sh
   npm ci --ignore-scripts
   npm start
   ```

3. يفحص البوت مكتبة Python عند البدء ويحاول تثبيت المتطلبات الناقصة مرة واحدة في `.venv-reader`، قبل تسجيل دخول القارئ. الإعداد لا يستخدم التوكن الحقيقي ولا يتصل بحساب ديسكورد. إذا فشل، يعرض المفسر والسبب ويستمر البوت الرسمي؛ تقارير أرينا تحتاج إصلاح القارئ.
4. جرّب `!status` للتأكد من إصدار البوت 2.1.0، ثم `!scan` و`!سجن`.

للتثبيت والفحص اليدوي:

```sh
npm run setup:reader
npm run check:reader
```

اترك `PYTHON_BIN` فارغًا لاستخدام بيئة المشروع. إذا عندك بيئة Python مخصصة ومجهزة، ضع المسار الكامل لمفسرها. اسم حزمة القارئ هو `discord.py-self` وليس `discord.py` الخاصة بالبوتات الرسمية.

## المتغيرات

يوجد `.env.example` كامل. استخدم متغيرات لوحة الاستضافة أو انسخه إلى `.env` واملأ:

```dotenv
DISCORD_BOT_TOKEN=
MONGODB_URI=
MONGODB_DB=snow_clan_monitor
ENCRYPTION_KEY=
READER_TOKEN=
PYTHON_BIN=
```

`DISCORD_BOT_TOKEN` للبوت الرسمي. `READER_TOKEN` للقارئ، ويمكن تركه فارغًا ثم ربطه من `/تحديث التوكن`. الاعتماد المحفوظ مشفّرًا في MongoDB له الأولوية عند بدء التشغيل. لا تشارك التوكنات أو رابط MongoDB بكلمة مروره.

في التثبيت الجديد فقط، ولّد مفتاح تشفير ثم احتفظ به ثابتًا وسريًا:

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

ضع الناتج في `ENCRYPTION_KEY`. عند الترقية احتفظ بمفتاحك الحالي؛ تغييره يمنع فك اعتماد القارئ المحفوظ.

الإعدادات الافتراضية:

| المتغير | القيمة/الغرض |
| --- | --- |
| `CLAN_GUILD_ID` | `1516358993939922994` |
| `ARENA_GUILD_ID` | `766953289409232896` |
| `CLAN_ROLE_ID` | `1470732413112942665` |
| `JAIL_ROLE_ID` | `766953289513172995` |
| `WARNING_ROLE_ID` | `1062648452191891466` |
| `LOG_CHANNEL_ID` | `1550714406529273936` — نفس شات اللوق الحالي |
| `COMMAND_CHANNEL_ID` | فارغ لجميع قنوات الكلان المتاحة |
| `SCAN_ALLOWED_ROLE_IDS` | رتب الإدارة المسموحة، مفصولة بفواصل |
| `TOKEN_ADMIN_IDS` | المعرّفات المخوّلة بتحديث اعتماد القارئ، بالإضافة إلى مالك السيرفر |
| `ALLOW_EVERYONE_SCAN` | `false`؛ تفعيله يتيح أوامر الفحص والحالة للجميع، ويظل السجن للإدارة |
| `EXCLUDE_BOTS` | `true` |
| `RECONCILE_SECONDS` | `300`؛ الحد الأدنى 60 ثانية |
| `SCAN_TIMEOUT_SECONDS` | `120`؛ انتظار مكتبة ديسكورد أو طلب جارٍ قد يزيد زمن الفحص |

فعّل **Server Members Intent** و**Message Content Intent** للبوت الرسمي من Developer Portal. ادعه إلى سيرفر الكلان بنطاقي `bot` و`applications.commands`، مع View Channel وSend Messages وEmbed Links وAttach Files وRead Message History. لم يعد البرنامج يطلب Guild Voice States Intent.

## الأوامر

| الأمر | الوظيفة |
| --- | --- |
| `!scan` | مقارنة أعضاء الكلان بحاملي رتبة الكلان في أرينا |
| `!scan ROLE_ID` | فحص رتبة أخرى في أرينا |
| `!سجن` | حاملو رتبة الكلان المسجونون أو أصحاب الإنذار، بمن فيهم الموجودون خارج سيرفر سنو |
| `!status` | إصدار البوت وحالة القارئ والحفظ وآخر فحص |
| `!help` | قائمة الأوامر |
| `/تحديث التوكن` | تحديث القارئ في نافذة خاصة لمالك السيرفر والمخوّلين |

التقارير تبقى رسالة واحدة بأزرار تنقل وتحديث وتصدير. الأزرار لصاحب الطلب المخوّل وصالحة 15 دقيقة. المنشنات المعروضة لا ترسل تنبيهات. تكرار وصول رسالة الأمر نفسها لا يعالجها مرتين؛ رسالة جديدة لها معرّف جديد تبقى طلبًا مستقلًا.

تحديث القارئ يتحقق من الاتصال ووجود الحساب في أرينا، ويحفظ الاعتماد مشفّرًا قبل تفعيله. فشل التحقق أو الحفظ يبقي القارئ السابق كما هو. لا توجد عملية تدوير آلية للتوكنات.

## آلية القراءة

- البوت الرسمي يبقى على Node، والقارئ عملية Python واحدة تدير اتصال حساب المستخدم عبر مكتبة كاملة. الاتصال الداخلي عبر stdin/stdout؛ لا يحتاج منفذ ويب للقارئ.
- يجلب معرّفات حاملي الرتبة المتاحة عبر `Role.fetch_members`، ويتحقق من معرّفات الكلان والمرشحين عبر `Guild.query_members` بدفعات حتى 100 معرّف. لا يحمّل قائمة أعضاء أرينا الـ270 ألف، ولا يستخدم بحثًا عامًا لاكتشاف الحسابات.
- طلبات القارئ مسلسلة بفاصل ثانية. تحترم المكتبة حدود الطلبات، وتُنقل المهلة الطويلة إلى Node لمنع طلبات جديدة خلالها. أخطاء الشبكة توقف القراءات الجديدة دقيقة.
- رفض الاعتماد أو طلب التحقق/كابتشا أو رفض الوصول لمسار أساسي يوقف القارئ لهذه الجلسة، دون حلقة إعادة دخول. لا تحاول تجاوز تحقق الحساب؛ راجع الحساب من التطبيق الرسمي قبل إعادة التشغيل أو التحديث المقصود.
- قد لا تتاح صلاحية حصر حاملي الرتبة أو عددهم للحساب. رفض تلك المسارات الاختيارية يؤجلها 15 دقيقة، وتبقى قراءة الأعضاء المحددين ممكنة؛ يظهر الحصر جزئيًا بدل إيقاف قراءة العضوية كلها.
- تستخدم واجهات المكتبة الرسمية داخل مشروعها، ولا توجد طلبات HTTP مباشرة بتوكن الحساب في JavaScript. تمرّر البيئة إلى Python اعتماد القارئ ومعرّف أرينا فقط مع متغيرات النظام اللازمة؛ لا تمرّر اعتماد البوت أو MongoDB أو مفتاح التشفير، ولا تُطبع استثناءات المكتبة الخام.
- تُمرّر أحداث العضوية والرتب المتاحة في أرينا ببيانات محدودة فقط، بما فيها تحديثات الأعضاء غير الموجودين في ذاكرة المكتبة. اشتراك بروتوكول السيرفر الكبير يتطلب typing؛ لا يسجل البرنامج محتوى الكتابة أو الرسائل أو النشاط الصوتي.

**التخزين هنا يحافظ على حداثة الرتب:** نتائج الفحص قابلة لإعادة الاستخدام 5 ثوانٍ إن لم يصل تغيير، وزر التحديث يجبر فحصًا جديدًا. تحفظ MongoDB آخر حالة للمقارنة واستمرار اللوق بعد إعادة التشغيل، وتُستخدم الحالة القديمة كمرشحين يُعاد التحقق منهم. لا نستخدم بيانات رتب عمرها 24 ساعة كدليل على عضوية حالية أو عقوبة جديدة.

لا يُصنّف العضو غائبًا بسبب مهلة أو خطأ صلاحية أو غيابه عن دفعة. الغياب يحتاج استجابة العضو غير الموجود `Discord 10007` من قراءة فردية مباشرة. الاكتمال يحتاج مطابقة العدد المعلن قبل الفحص وبعده مع العدد المتحقق؛ وإلا يبقى التقرير جزئيًا.

واجهة الرتبة قد توفر حتى 100 حامل فقط. دمجهم مع أعضاء الكلان والأسماء المعروفة قد يكمل الحصر، لكنه لا يضمن اكتشاف حامل خارجي لم يصل معرّفه. سرعة الفحص وتغطية الأحداث تعتمدان على وصول الحساب وحدود ديسكورد.

## المراقبة واللوق

تبقى مراقبة إعطاء/إزالة رتبة الكلان، ودخول/خروج الكلان وأرينا، ولوق الحصول على السجن أو الإنذار في `LOG_CHANNEL_ID` نفسه.

أول رصد للحالة الحالية يكوّن أساسًا ولا يرسل عقوبات قديمة كأنها جديدة. تكرار الحالة أو إعادة التشغيل لا يعيد إنشاء اللوق. إزالة العقوبة تحدّث الحالة بصمت؛ رصد إعطائها لاحقًا يولد لوقًا جديدًا. الاكتشاف بالمراجعة يحمل وقت الاكتشاف، ولا يدّعي وقت الإعطاء الفعلي أثناء الانقطاع.

يحفظ MongoDB الحالة والطابور في `monitor_members` و`monitor_state` و`monitor_outbox`، والاعتماد المشفّر في `monitor_settings`، وقفل النسخة الواحدة في `monitor_leases`. القفل الموجود يمنع نسختين على نطاق الإعدادات وقاعدة البيانات نفسها. بعد توقف قسري قد يلزم انتظار انتهاء القفل، حتى 90 ثانية. اختلاف قاعدة البيانات أو النطاق لا يشارك القفل؛ شغّل نسخة واحدة.

## حل المشكلات

| الكود/الحالة | الإجراء |
| --- | --- |
| `.env not found` | طبيعي إذا كانت المتغيرات في لوحة الاستضافة |
| `READER_PYTHON_MISSING` | وفّر Python 3.10+ أو صحح PYTHON_BIN |
| `READER_PACKAGE_MISSING` / `READER_PACKAGE_VERSION` | راجع الإعداد التلقائي أو نفذ setup:reader ثم check:reader |
| `READER_PACKAGE_CONFLICT` | استخدم بيئة Python مخصصة للقارئ؛ اترك PYTHON_BIN فارغًا للبيئة المحلية |
| `READER_IMPORT_FAILED` | check:reader يعرض نوع الخطأ واسم الحزمة المفقودة إن توفر |
| `READER_AUTH` / `READER_VERIFICATION` | توقف القارئ؛ راجع الحساب وتأمينه والتحقق المطلوب قبل تشغيله مجددًا |
| `ARENA_NOT_JOINED` | الحساب غير موجود في ARENA_GUILD_ID أو لم يعد له وصول إليه |
| `OPTIONAL_ACCESS` | مسار تعداد/عدد الرتبة غير متاح؛ قد يبقى الفحص جزئيًا |
| `RATE_LIMIT` | انتظر المهلة؛ لا تعد التشغيل لتجاوزها |
| انتظار قفل التشغيل | أوقف النسخ الزائدة واترك القفل السابق ينتهي؛ لا تكرر إعادة التشغيل أثناء الانتظار |

تغيير المكتبة لا يضمن منع قفل الحساب أو الحظر، ولا يعالج تسرب اعتماد سابق. يجب أن يكون القارئ حسابك وله الوصول إلى أرينا. لا يشترط إضافة البوت الرسمي إلى أرينا.

## التحقق

```sh
npm test
npm run test:reader
npm run check
npm run check:reader
```

الاختبارات تحاكي اتصال Python والفحص والرتب والأحداث وتؤكد حذف الأمر السابق دون تسجيل دخول حساب حقيقي. اختبار MongoDB الحقيقي اختياري عبر `MONGO_TEST_URI` لنسخة مؤقتة على 127.0.0.1 فقط، ولا يستخدم قاعدة الإنتاج. راجع `TEST-RESULTS.md` للنتائج وحدودها.
